## 1. 裁剪判据

核心链路为“移动沟通 → 范围确认 → 后台任务 → 实际验收/独立复核 → 可靠通知”。每项功能必须说明服务哪个核心环节。符合任一条件进入裁剪清单：与新运行底座重复；绕开产品授权/验收；把不同状态混成成功；为未验证能力提供自动执行入口；与核心链路无关且无明确用户需求。

“暂时关闭菜单”不算源码删减完成。源码删除必须有依赖盘点、数据和旧链接去向、替代验收、负例和回退依据。用户明确要求的 Agent 连接、原生旧会话访问、中文化、工作流可视化与共享记忆不因“简化”消失。

## 3. 最小产品界面

默认仅保留：仪表盘、对话/任务、运行与验收、Agent/原生会话、设计工作流、日志/通知、设置。微信绑定、模型/记忆状态、暂停/取消、待审批和待核对都应可见。

外部 forge/tracker、商业/宣传入口、复杂 variant竞技界面、第二套流程编辑器及第三方主题套件不占核心导航。原有 Git 差异、提交和原生 run历史支撑代码验收，不属于可随意删的“GitHub功能”。用户已有明确需求的高级功能保留为隔离的可选模块，不强制移除。

代码裁剪结束时，关闭的非核心模块应不再被默认 bundle/API/调度器引用；若源码保留作为插件，要如实登记“隔离保留”，不称“已删除”。

## 4. 必须保留的底线

| 对象 | 原因 |
| --- | --- |
| 原始收件、游标、payloadDigest和重复提交保护 | 删除会重新出现静默丢失/冲突 |
| ReplyOutbox正文、clientId与投递证据 | 执行结束不代表用户收到 |
| Grant/Approval/预算/租约与目录/网络硬约束 | 不能用依赖精简换取自动越权 |
| Evidence、immutable checks、独立Reviewer、completionProof | 不让仅exit0或模型自述变成最终完成 |
| 原生SessionRef、活动冲突检查、源码/来源及兼容索引 | 用户明确要求旧对话，不能偷偷改新会话 |
| archive、Mem0、事实质量状态和用户隐私控制 | 压缩和长期事实不互相替代 |
| 单owner/fence、迁移manifest、一致性备份和回退 | 防重复执行，不拿删文件代替安全退役 |
| 中文、键盘/屏幕阅读器、错误提示和本地日志 | 核心可用性与抽查入口 |
| 上游许可证/版权及必要notice | 裁剪不得破坏开源归属 |

用户本机的 Codex/OpenCode/Kimi/Claude Code/WorkBuddy/Devin/Antigravity/DeepSeek Harness App 本体、认证和历史均不属于本项目垃圾清理目标。不删机器目录，不删原生对话或私有日志数据来“让项目更小”。

## 5. 必做工作包 P6c：收敛后物理删除

P0 记录引用图和裁剪 manifest；P2/P4 先替换权限/调度；P5 缩小默认入口；G5 迁移/回退通过后执行 P6c。P6c 是强制子阶段，通过 G5c 裁剪门槛后才做 P7 耐久与发布。

1. 精确登记 C01–C15 的产品依赖、数据/链接归属、接替实现、owner、风险和引用。
2. 替代路径通过，旧已接收内容可读、未结束任务 drain或保留核对；不能靠清空数据库完成。
3. 禁止新增旧路径请求，并移除对应产品 route/import/launch/定时器。
4. 引用归零后，在当前产品 fork删除明确列出的源码、测试旧分支、依赖与构建资产；迁移/负例测试保留或更新。
5. 编译、核心回归、静态引用、无多余外发、数据守恒与回退负例一起验收。
6. 保留封存的0.2.2发布工件用于回退。新版本不长期携带两个活跃执行器；过渡期薄兼容facade只能路由指定旧待办，不接受新任务。每个旧任务都有核对状态和接续 owner，drain/核对完成后停止兼容服务并删除活跃旧实现。

删除应以可恢复的版本化变更提交进行，不对宽目录递归清理。材料删减须列出精确文件和恢复方式；源代码可从旧发布恢复，但旧数据备份不能覆盖新数据。

## 6. 裁剪验收与期限

[验收矩阵](0.3.0-validation.md)增加 V46–V52，总计52项。每项 C需有状态：待盘点/待替代/待drain/可删除/已删除/隔离保留/不新建，以及下一门槛；“永久兼容”不能作为默认结案。具体精确文件 manifest 在 P0 形成，当前表不是整目录删除授权。

- 未使用依赖/产物不得存在于默认产品构建，无额外遥测/宣传请求。
- 同一请求、任务和schedule只有一个实际执行owner。
- 删除旧缓存/队列前后，收件、待发和历史关联计数/摘要守恒。
- 权限、验收、旧会话、中文和可访问性负例不退化。
- 每个C要么已删，要么有必要兼容理由、有限范围和退役门槛；未解释旁枝不得以“可选”长期混入核心。

G5c 放行条件：V46–V52 有实际验收证据；默认产品内重复运行驱动已经退役；旧待办清单已清零或逐条转为不执行的可追溯待核对记录；隔离保留/不新建项有明确原因。凡仍靠旧活跃调度器自动执行的条目不得算裁剪完成，应继续灰度或预览，而不是宣称 0.3.0 已完成。运行诊断或结果补发不属于第二个执行引擎，但其 owner 与终止条件也要登记。

auto-allow是基线盘点发现的历史差距；后续源码替代有27项权限/身份/锁证据，不能据此宣称现役已切严格模式或G5c已过。本轮只整理处置与状态，没有物理删除、移动用户数据或重启服务。
