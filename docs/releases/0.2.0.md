0.2.0 已部署持续目标执行器。真实模型已完成受控文件修复，也已通过失败后自主进入下一轮的试运行。首版是独立副本里的代码修复路线，不是任意本机 App 的无人值守控制器。

## A 已落地的运行路线

```flow TB
你确认目标与范围 -> 持久目标与授权
持久目标与授权 -> 常驻调度
常驻调度 -> Kimi规划
Kimi规划 -> 官方DeepSeek提出修改
官方DeepSeek提出修改 -> 受控副本应用
受控副本应用 -> 固定真实验收
固定真实验收 -> {通过?}
通过? -> Kimi独立复核: 是
通过? -> 保存失败记录: 否
保存失败记录 -> 常驻调度: 下一轮
Kimi独立复核 -> {目标达标?}
目标达标? -> 完成并保留证据: 是
目标达标? -> 保存失败记录: 否
```

- 一次授权绑定目标版本、文件范围、检查和预算。
- 失败自行返工，不逐轮请求人类批准。
- 当前文件指纹、成功退出码与独立审查共同决定完成。
- 预算、期限、无进展和暂停均由程序校验。
- 全局暂停落盘。停机后未完成的执行等待核对，不盲目重派。

## B 怎样使用和抽查

仪表盘新增“持续目标 · 自主验证”。先创建草稿，再展开范围，最后确认启动。卡片显示每轮检查、独立复核、文件指纹与结果副本路径。

微信可以发 `/目标` 查询。还支持 `/目标 查看 <ID>`、`/目标 暂停 <ID>`、`/目标 恢复 <ID>`。`/目标 暂停全部` 停止全部目标；恢复不会提高旧预算。

微信确认须复制完整范围摘要，不能由聊天模型代签。改方向先暂停，再更新草稿并重新确认。原项目文件和原生 Agent 旧会话不被这条路线覆盖。

| 组件 | 地址或位置 |
| --- | --- |
| 仪表盘 | http://127.0.0.1:4321 |
| 持续目标服务 | http://127.0.0.1:4326/health |
| 常驻定义 | com.markus.personal-ai-os.goals |
| 私有状态与副本 | ~/.local/state/personal-ai-os/goals/ |
| 命令行抽查 | npm run goal-status；npm run goal-status -- get goal_ID |

## C 验证结果与边界

真实修复：一轮完成，使用 1,497 token。真实自动返工：先出现一次合成验收故障，第二轮自行通过，使用 4,181 token。私有证据存储切换后复测通过，使用 4,145 token。所有试运行保留原始测试项目，未发送真实微信测试消息。

本地测试覆盖权限、路径、并发租约、暂停、预算、重启、文件指纹、独立审查与真实 macOS Seatbelt。检查程序不能修改验收文件，不能读取工作区外的私有测试文件，也不能联网。

首版只支持已有文本文件和固定 `node --test` 验收。输入会发送给已有 Kimi 与官方 DeepSeek，不是全离线。token 上限不等于精确美元账单。该回环服务按单人、本机可信应用设计，不是多用户 RBAC 系统。

仍未验收：24 小时合盖耐久、任意 GUI/CLI App 自主执行、自动合并到原项目、外部事件订阅、真实微信消息回包。前端构建与组件回归通过，但浏览器自动导航仍超时，不能算实页验收成功。

下一版应先扩展可强制约束的原生 Agent adapter，并做端到端、夜间与主机故障验证。没有这类证据的 App 仍显示待验证，不能当作无人值守通道。
