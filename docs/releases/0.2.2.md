自动恢复机制已部署。未派发的请求可重试，已生成的结果只补发。受控目标能接续保存的提案；副作用不明的任务先查明确证据，不把原指令整条重跑。

## A 中断后走哪条路

```flow TB
发现中断 -> 读取持久检查点
读取持久检查点 -> {已执行到哪一步?}
已执行到哪一步? -> 确认尚未派发
确认尚未派发 -> 退避重试: 容量和旧进程安全门槛
已执行到哪一步? -> 结果已经生成
结果已经生成 -> 持久文本补发: 不调用Agent
已执行到哪一步? -> 受控目标提案已保存
受控目标提案已保存 -> 核对授权与副本
核对授权与副本 -> 接续剩余修改
接续剩余修改 -> 真实验收与独立复核
已执行到哪一步? -> 执行结果不确定
执行结果不确定 -> 查询明确关联的Task
查询明确关联的Task -> {有匹配完成凭据?}
有匹配完成凭据? -> 持久文本补发: 有测试和复核
有匹配完成凭据? -> 通知并等待核对: 无
```

已完成的 Task 与当前文件指纹吻合时，修复未落盘的 Goal 结案状态，不重做任务。对不明原生 App 操作，这条机制不会猜测它已经执行或尚未执行。

## B 恢复有预算，也尊重停止

| 环节 | 规则 |
| --- | --- |
| 后台巡检 | 每 5 秒检查持久收件和文本补发 |
| 未派发失败 | 15/30 秒退避；第 3 次失败后待核对 |
| 容量或旧进程占用 | 保留排队，等安全退出；不消耗失败预算 |
| 文本补发 | 最多 96 次外层尝试；退避从 15 秒至 15 分钟 |
| 受控目标 | 新授权包含恢复策略，默认最多 3 次；原预算不增加 |
| 用户取消或重置 | 停止相关追办和补发，原文仍保留 |
| 权限过期、文件冲突、未知活跃验收 | 不强行接续，保留待核对状态 |

微信发 `/消息` 看重试、待补发和待核对。`/acp-more` 只重试补发文本，不重新执行任务。仪表盘持续目标卡片显示恢复次数及原因。

## D 不能承诺的部分

```callout warn 有边界的自恢复，不是无条件重跑
任意原生 App 的未知副作用、未知活跃验收进程和冲突检查点仍需核对。前台 ACP 仍有 5 分钟上限。未实现原始语音 ASR或二进制附件的持久补发。
```

复用 clientId 有助于避免重复文本，但不保证服务器 exactly-once。发送接口接受不代表用户已读。旧版本丢失的语音原文不能重建，旧目标也不会自动获得新授权。

本轮没有真实微信回包或 24 小时合盖耐久验收。新发一条语音可抽验实际回包，不能用构建结果替代它。

回退前先停止桥、备份收件和补发目录。不要删除待办或批量重放 uncertain 记录；停用恢复配置只停止自动巡检，须保留原数据。
